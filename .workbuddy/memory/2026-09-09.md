## 窗口尺寸优化：默认尺寸收紧 + 尺寸记忆（已完成并验证）

**需求：** ①默认初始窗口过大，调整为内容完整展示的合理尺寸；②窗口大小记忆——手动调整后持久化，下次启动恢复；从未调整过则用默认。

**实现：**
- `src/config.py`：Settings 新增 `window_size: Optional[str] = None`（"宽x高"），加入 `_SERIALIZED`；`_coerce` 按 str/None 处理；`validate()` 校验格式（非 `int x int` 置回 None 并告警）。
- `src/ui.py`：
  - 默认尺寸 `DEFAULT_WINDOW_SIZE = (1040, 720)`（原 1200x860；1040 保证顶栏 标题+状态+数据源 radio+极简按钮 不挤、底部 7 按钮放得下、左栏树/右栏详情都完整）。
  - `__init__`：geometry 改为 `self._initial_window_size()`——优先 settings.window_size，非法/缺省回落默认；收敛到 [minsize(1000x680), 屏幕尺寸]（防换显示器出屏）。
  - 记忆机制：`self.bind("<Configure>", _on_window_configure)` + 600ms 后才 `_enable_win_size_tracking`（启动期间程序性尺寸事件一律忽略）；`event.widget is self` 过滤子组件事件（toplevel 的 bindtags 会收到所有后代 Configure）；拖拽缩放防抖 500ms（after_cancel+重排）→ `_save_window_size`：zoomed(最大化) 不记录保留最近正常尺寸、与上次已保存相同跳过、写入 settings.window_size 并 save()。
- `tools/screenshot_minimal.py`：改用临时 config_path，避免截图驱动污染真实配置（窗口尺寸/极简偏好）。

**测试：** 新增 `tests/test_window_size.py` 5/5 OK——默认尺寸且不写配置文件、调整→防抖持久化→新实例恢复、小于 minsize 收敛 1000x680、非法值 validate 置 None+告警+UI 回落默认、配置往返不丢。`tests/test_minimal_mode.py` 9/9 回归 OK。
**测试陷阱：** 双实例测试时第二个 Settings 必须走 `apply_dict(load_config_file())` 模拟真实 build_settings 读盘路径，直接 `Settings(**kw)` 构造读不到磁盘保存值（第一次跑挂 3 个全是这个原因）。

**运维复盘（GUI 进程管理）：** 之前"pythonw 30s 内消失"的真相——bash 后台任务启动的实例其实一直活着，是 `tasklist | grep` 的检查时点/输出误报；PowerShell 工具会话启动的子进程才会被会话回收连带杀掉。由此导致过双实例并存（9J2eC4 误报消失后又启了 EN194J），双实例会 last-writer-wins 互相覆盖 chiplookup.json——正是极简偏好"没记住"的可能帮凶之一。后续：GUI 一律 bash 后台启动；启动新实例前先 `Stop-Process` 全部 pythonw 并确认清零；判断存活以 `grep -c` 或 Stop-Process 前后的任务通知为准，不以单次 grep 误报定论。

## P0 三项修复（已完成并验证）

用户确认「先处理P0」。三项全部落地，回归 59 用例全绿（window_size 8 + minimal 9 + modes 37 + tree_columns 5）。

**P0#1 列宽裁切（`_fit_tree_columns` 重写）：**
- 真根因（修正报告原描述）：缺口场景（avail < Σ最小宽=328px）把缺口全记在料号列（`pn = avail - sum(其余min)`，容量独占 130px）→ 料号仅 24px。
- 解法：三档常量 PREFERRED（接近完整内容）/ FLOOR（硬底线）/ DEFICIT_W（缺口权重，料号 0.46 最高）；缺口时 FLOOR 起步 + 权重分配 + 单列封顶（水量填充，触顶回流）；极窄按 FLOOR 等比压缩；自定义列宽 FLOOR 托底、冲突回落标准分配（`_tree_col_custom` 不清，宽了仍保手感）。左栏默认占比 30%→40%（1040 下 avail≈364，料号 128px 完整可读）。`_on_col_drag` 改 FLOOR 托底。
- 修复后：默认 14 字符（K4A4G165WF-BCW）、极简 15 字符完整、最小尺寸 13 字符。

**P0#2 DPI 感知：**
- `main.py` `_enable_dpi_awareness()`：创建 Tk 前 `SetProcessDpiAwareness(1)`（Vista 回退 `SetProcessDPIAware`）。
- `ui.py` `_ui_scale` 因子 + `_s()` 助手；**关键教训：`winfo_fpixels('1i')` 由字体度量推导（本机实测 96.0946/96），直接除会引入 ~1% 漂移（s(1000)=1001），必须走 `GetDpiForSystem()`/`GetDeviceCaps(LOGPIXELSX)`（DPI 未感知进程被虚拟化返回 96 → 测试环境因子恒 1.0）**。模块级 `_win_dpi_scale()` 供 App 与 SlimVScrollbar 共用。
- 窗口尺寸改逻辑像素语义（配置存逻辑值 ÷factor，恢复乘 factor，跨缩放稳定）；minsize/默认尺寸/行高/表头高/列宽/分栏常量/滚动条全经 `_s()` 缩放；`_LEFT_PADX` 实例化缩放。
- **WM 行为坑：客户区顶满屏幕高时（864 请求），标题栏装饰放不下 → WM 压窗 + Tk 强制回 minsize（850）**；`_initial_window_size` 高度收敛预留逻辑 60px 余量。比例权重字典严禁走 `int(round(0.46))` 缩放（全变 1 → 等权退化，实测踩坑后 `_col_metrics` 只缩放像素字典）。

**P0#3 蓝钮对比度：** 白字→深字 `#0e1620`（5.6:1，与绿钮设计语言统一）；active 底改浅蓝 `#6aa9ec`（深字 7.5:1，原 #2563eb 会倒挂 3.6:1）；disabled 补浅字映射 `#b0c4d4`（5.1:1）。
