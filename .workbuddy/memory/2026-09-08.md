## 数据源切换卡顿根因分析（已完成，未改代码）

定位结论（离线缓存命中实测，纯 CPU/IO）：
- 切到 upstream/hybrid 冻结 ≈9–12s；local 仅 0.01s。
- 主因：`src/upstream.py` `build_upstream_records`（154-173 行）对 39,934 条记录（marks 17,580 + pn 22,354）逐条调 `engine.decode_part` 做规格补全解码，实测 ≈10.1s，占切换 90%+。
- 次因：切换在 Tk 主线程同步执行 —— `ui.py:_set_source_mode`(915) → `make_source`(sources.py:390) → reload；`UpstreamProvider.load`(upstream.py:200) 每次重建索引(0.25s)+重编译引擎(0.19s)，无进程内缓存。
- 网络放大项：`fdnext/indexes.py:192-238` ensure_index_cache 在缓存缺失/过期(7天)/refresh 时同步下载 4 个文件，每文件 2 源×(retries+1)=3 次、单次 timeout 30s（默认），弱网可达分钟级；重试为串行指数退避。
- 切换后体验：记录数从本地 32 → 4 万，`search.py` 每按键对 4 万行×9 字段做 difflib 全扫，实测单次查询 2–4s，`ui.py` 无防抖。
- 打包隐患：`ChipLookup.spec` 的 datas 只含 `data/`，未打包 `src/fdnext/data/fdnext-core-3.2.0` 快照 → exe 内 `resources.snapshot_dir()` 为空，引擎会走 GitHub 联网下载规则（%LOCALAPPDATA%/chiplookup/fdnext-rules），首次切换极慢。

改进方向（按优先级）：
1. 切换/加载移入后台线程 + `after()`/队列回主线程刷新，禁用单选钮防重复触发。
2. 记录构建时跳过批量解码（改为详情查看时懒解码），或对唯一 model 做解码缓存（模块级 memo，跨切换复用）。
3. app 级数据源缓存：按 (mode, priority, offline, 索引 mtime) 键复用已建 source，来回切换不重建。
4. 搜索：输入防抖(150–250ms)、命中即短路、去除逐字段 SequenceMatcher 全量模糊（先精确/前缀/子串，模糊只对候选子集）。
5. 网络：切换走离线缓存优先 + 后台静默刷新；降低默认 timeout；`_download` 失败快速失败。
6. spec 增加 fdnext 快照 datas 项。

- `style.layout("Candidate.Treeview.Heading", ...)`：把 `Treeheading.text` 的 `sticky` 从默认 `"we"` 改为 `"nsew"`，让文字真正水平和垂直居中。

**验证：**

## 表头水平对齐根因修复（用户截图三问"发现问题了吗"）

**用户截图暴露两个问题：**
1. 表头标题与下方单元格文字**水平错位**（左锚定列统一右偏 7-8 物理px）——与拖不拖宽度无关，一直存在。
2. 用户拖过列分隔线后列宽分布错乱（料号被挤窄、型号文字被裁）。

**根因（Tk 坐标 + 像素双重实测）：**
- Treeview 单元格文字有 **~4 逻辑px 固定水平内边距** + 树内容区 **2px 左边框**（bbox[0]=2）；自绘表头 label 直接贴列起点放，标题比数据文字左偏 (2+4)×1.25≈7.5 物理px。校准 `_CELL_TEXT_PADX=4`、place x 加 off=2 后归零；残留 ±1 逻辑px 是 DPI 逻辑↔物理取整抖动（窗口物理位置奇偶性决定，同代码两次运行可差 1px），肉眼不可见，接受。
- **自绘表头拖列坐标 bug**（上一轮引入）：label 上的 `event.x` 是 label 相对坐标，直接传 `_divider_index_at` 会判空/判错线（实测 label 内 x=198 判成 i=None，正确 tree 坐标 444 判成 i=1）。新增 `_tree_event_x()`（用 `winfo_rootx` 差换算到树坐标系）。
- tk.Label 默认 `padx=1`，会让文字整体再右偏 1px，显式 `padx=0`。
- 树区域（数据行）不再有列宽拖拽热区：`_on_tree_motion/_on_tree_press` 仅在自绘表头上生效，树上的点击放行给原生行选择；光标是 per-widget 的，新增 `_set_drag_cursor()` 统一设置 header_frame/labels/tree。

**验证：** 420/640/870px 三种面板宽度下，左锚定列文字起点差、居中列中心差均 ≤1 逻辑px；分隔线判定 label 内坐标 → i=1 正确；`tests/test_modes.py` 37/37 OK（82.3s）；宽面板截图 `screenshots/align_final_wide.png` 五列全对齐、型号完整显示。
- 教训：像素测量时 ImageGrab 抓的是屏幕，被遮挡窗口会截到别的应用，需 lift+topmost；蓝色选中行检测要限制 x 范围避开顶栏蓝色按钮。
